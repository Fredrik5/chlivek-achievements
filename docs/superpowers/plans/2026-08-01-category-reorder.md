# Admin Category Reordering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an admin reorder categories, and have that order reflected both in the admin "Kategorie" panel and in category grouping on the player dashboard.

**Architecture:** Add an `order` integer column to `Category`, backfilled to match today's implicit `createdAt` order. Category-affecting listing endpoints sort by `order` (categories) and by `[category.order, achievement.order]` (achievement feeds) instead of `createdAt`/`categoryId`. A new admin-only endpoint swaps the `order` of two adjacent categories. The admin UI gets up/down buttons per category chip that call this endpoint.

**Tech Stack:** Next.js 16 (App Router, route handlers), Prisma 7 (`prisma-client` generator) against SQLite, React 19 client components, no test framework in this repo (verification is manual/DB-script based).

## Global Constraints

- Categories are a flat, non-nested list — reordering has no per-parent scoping (spec: "Scope").
- Achievement ordering within a category is unchanged; this plan does not touch `Achievement.order` (spec: "Scope").
- Uncategorized achievements (`categoryId = null`, "Ostatní") keep today's incidental position in the sort — not addressed by this plan (spec: "Scope").
- Migration must be a visual no-op: today's implicit `createdAt` order becomes tomorrow's explicit `order` value (spec: "Data model").
- New categories append to the end (`max order + 1`) (spec: "Order assignment rules").
- Per this user's global instructions: **show the exact migration SQL and wait for explicit approval before applying it** — do not run `prisma migrate dev` to apply schema changes without that approval step.
- Per this user's global instructions: do not create git commits unless the user explicitly asks for them in this session, even though each task below ends with a "commit" step description — treat those as "stage this as a logical unit", and only actually run `git commit` if the user has asked for commits in this conversation.
- All admin routes require `requireAdmin()` (existing convention in every `/api/admin/*` route).
- Match existing code style: inline `style={{ ... }}` objects using CSS custom properties (e.g. `var(--space-3)`), no CSS-in-JS library, Czech UI copy (e.g. "Něco se pokazilo.").

- [ ] **Step 3: Hand-edit the migration to add the backfill**

Open the generated `migration.sql` and append this backfill statement at the end of the file:

```sql
-- Backfill: number categories 0, 1, 2, ... by their existing createdAt so
-- this is a no-op for today's visible order.
UPDATE "Category"
SET "order" = (
  SELECT COUNT(*)
  FROM "Category" AS c2
  WHERE (
    c2."createdAt" < "Category"."createdAt"
    OR (c2."createdAt" = "Category"."createdAt" AND c2."id" < "Category"."id")
  )
);
```

### Task 3: Category reorder endpoint

**Files:**
- Create: `src/app/api/admin/categories/[id]/reorder/route.ts`

**Interfaces:**
- Consumes: `requireAdmin()` from `@/lib/auth`, `handleApiError` from `@/lib/api`, `prisma` from `@/lib/db`.
- Produces: `POST /api/admin/categories/:id/reorder` with body `{ direction: "up" | "down" }` → `{ ok: true }` on success (200) or `{ error: string }` (400/404), consumed by Task 5's UI.

- [ ] **Step 1: Implement the endpoint**

Create `src/app/api/admin/categories/[id]/reorder/route.ts`:

```ts
import { NextRequest, NextResponse } from "next/server";
import { prisma } from "@/lib/db";
import { requireAdmin } from "@/lib/auth";
import { handleApiError } from "@/lib/api";

export async function POST(
  request: NextRequest,
  { params }: { params: Promise<{ id: string }> },
) {
  try {
    await requireAdmin();
    const { id } = await params;
    const body = await request.json();
    const direction = body.direction;

    if (direction !== "up" && direction !== "down") {
      return NextResponse.json({ error: "Neplatný směr." }, { status: 400 });
    }

    const category = await prisma.category.findUnique({ where: { id } });
    if (!category) {
      return NextResponse.json({ error: "Kategorie nenalezena." }, { status: 404 });
    }

    const siblings = await prisma.category.findMany({
      orderBy: [{ order: "asc" }, { createdAt: "asc" }],
    });

    const index = siblings.findIndex((s) => s.id === id);
    const neighborIndex = direction === "up" ? index - 1 : index + 1;
    const neighbor = siblings[neighborIndex];

    if (!neighbor) {
      return NextResponse.json({ ok: true });
    }

    await prisma.$transaction([
      prisma.category.update({ where: { id: category.id }, data: { order: neighbor.order } }),
      prisma.category.update({ where: { id: neighbor.id }, data: { order: category.order } }),
    ]);

    return NextResponse.json({ ok: true });
  } catch (err) {
    return handleApiError(err);
  }
}
```
